# 系统验收与故障演练

统一入口为 backend/scripts/run_acceptance.py。每次使用新的批次目录，生成 report.md、report.json、各阶段日志和独立证明文件；不会拿历史通过记录补齐本次缺项。验收前后记录代码指纹，期间代码变化则不能给出完整通过结论。

## 执行

从项目根目录，使用 backend 的 Python：

~~~bat
backend\.venv\Scripts\python.exe backend\scripts\run_acceptance.py --node E:/node/node.exe --ros-components
~~~

Node.js 在 PATH 时可省略 --node；不加 --ros-components 则不运行 ROS 组件检查，报告会明确标记该范围。Linux 用 backend/.venv/bin/python，协议演练使用本机 mosquitto；Windows 使用 WSL Ubuntu-24.04 中的 mosquitto。需要 MySQL 的独立测试库创建权限、已安装的前端依赖及对应 ROS 工作区。

输出位于 docs/validation/runs/时间戳-随机编号/。可用 --output 指定一个尚不存在的目录；拒绝复用旧目录。最近批次位置记录在 .runtime/acceptance/latest.json。命令成功退出仅代表本批所有选定阶段通过；缺少证明文件、失败、未实际执行测试或验收期间改代码，都不能算完整通过。请勿使用 -O 或 PYTHONOPTIMIZE 关闭断言。

## 阶段与真实边界

| 阶段 | 实际执行 | 替代或不覆盖的部分 |
| --- | --- | --- |
| 前端构建 | Vite 生产构建，锁定的本地依赖 | 不代替所有屏幕尺寸的人工体验验收 |
| 后端回归 | 独立 MySQL、真实本地 HTTP 权限与事务测试 | 模型与部分连接故障使用测试替身 |
| 跨模块故障演练 | 独立 MQTT broker、HTTP 身份、MySQL、SQLite、重连、取消、告警复检 | 机器人是协议测试端，不执行运动；视觉为确定性数据 |
| 分析进程恢复 | 强制结束真实分析进程，启动新进程接回租约 | 模型为测试替身，租约缩为 2 秒；生产仍为 60 秒 |
| 服务启停与诊断 | 真实受管服务、前端静态资源、重复启动、正常退出、故障就绪码 | 使用隔离的不可达 Redis/MQTT 端口注入故障 |
| ROS 组件（可选） | 独立 ROS 域中的组件和地图可达性测试 | 不启动 Gazebo、不代表实际导航与物理停车验收 |

默认不调用付费模型，不向当前运行的机器人发送任务，不停止本机共享的 MySQL、Redis、MQTT 或业务服务。测试消息服务使用自己的端口和配置，停止前核对进程配置身份；业务实例使用动态端口及 require-new，拒绝复用其他实例。

## 跨模块故障场景

1. 无遥测时，操作员创建任务返回冲突，数据库中没有漏建的任务。
2. 后端 MQTT 断连时，已创建指令保留在事务发件箱。重连后下发；同一 HTTP 幂等键和同一 command_id 不会重复建任务或执行。
3. 相机结果由协议测试端代发。消息 broker 已确认收到、但后端未做应用确认时，SQLite 仍保留消息；重新打开 journal 并重连后，结果和分析任务各只出现一次。
4. 第一次视觉调用注入失败，不提前生成最终结论或告警；重试后由固定数值规则判定 1.20 MPa 越界，原子生成一条结果和一条告警。测试仅加速 available_at 的等待时间。
5. 登录操作员确认、记录处理并发起设备复检。0.45 MPa 的正常图像判定先于任务结束时，告警仍保持复检中；任务成功完成后关闭。客户端伪造的处理人与创建人被服务端身份覆盖。
6. 取消发生在待下发阶段，取消确认到达前占用不释放；重开机器人 journal 后收到确认才释放。后到的旧巡检指令被取消墓碑拦住，不能复活任务。

## 仍需单独验证

本批不是工业现场准确率或性能基准。柜门开启漏检、多光照/遮挡视觉评估、真实硬件制动、长时间负载与多进程扩容不在这套自动验收的通过范围中。视觉结果仍需要复核，后台目前按单业务进程部署。

遇到失败，先查对应阶段日志和输出证明；不要清空业务数据库或手动释放机器人占用来让测试变绿。保留失败批次，修复后重新生成新批次，便于对照。
