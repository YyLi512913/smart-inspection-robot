# 演示与录屏脚本

建议先用“证据复盘”录一版稳定的五分钟演示。它不修改现场状态、不调用模型，也不要求为了录屏重置数据库。本文提供分镜和讲述提纲，不代表已经生成视频。

## 演示前检查

- 打开本机 http://127.0.0.1:8010 ，使用已创建的管理员账号；不录制输入密码、模型配置或本地 .env。
- 在“运行状态”确认依赖及后台处理正常。机器人离线应如实展示并排查，不在页面里伪造在线状态。
- 检查历史压力表告警与对应图片是否仍在本地。证据文件可作为备选，不把备选照片说成当前画面。
- 准备 [完整验收报告](validation/runs/20261109T083843Z-dc0bee62/report.md) 与 [架构图](architecture.md)。
- 角色演示用管理员预先创建的查看账号；不更改当前唯一管理员的角色，不公开账号密码。

## 路线 B：现场执行一次仿真巡检

适合需要展示机器人运动的场合，时间留足 8–12 分钟。会产生新任务并可能调用配置的语言/视觉模型。开始前确认拥有该仿真场景、没有在途任务、电量足够且图片目录共享正确。

1. 从设备台账选择 AIR-001，点击安排巡检，让助手先说明检查项、设备和续航；核对方案后再执行。
2. 展示任务接单、Nav2 行驶、到点停稳与图片到达。不要把地图中图标移动代替实际导航效果；必要时同时显示 Gazebo 窗口。
3. 如要展示异常，在自己控制的仿真场景中切换压力表的可见状态，重新执行巡检。状态切换只改变场景，不向模型注入答案。
4. 产生告警后，在页面记录确认依据和处理措施；恢复可见压力，再发起关联设备复检。
5. 观察 task DONE 与逐项正常后告警关闭。若读不清或模型失败，保留复核状态并解释，不能手改结果。
6. 演示取消时，应选安全的仿真任务，等待取消确认后再创建下一项任务；不要将后端 CANCELED 截图当作物理停车证明。

可见状态切换命令在 [设备说明](equipment-inspection.md)。不为了演示直接删除 SQLite 日志、清空占用表或修改检查阈值。模拟电量耗尽时应按运行说明正常恢复仿真，不把恢复后的电量当成真实充电效果。

## 快速展示可靠性

若时间允许，可只运行不调用模型、不移动机器人的跨模块故障演练：

~~~bat
backend\.venv\Scripts\python.exe backend\scripts\system_fault_acceptance.py
~~~

它使用独立 MySQL 数据库及消息服务，输出断连、去重、结果补报、复检关闭和取消确认的检查结果。明确告知观众它是协议级演练；实际导航证据与之分开。

## 录屏组织

建议录制应用窗口、架构图和终端的必要区域，按分镜切换；控制台只显示命令和验收摘要，不展示配置文件、请求 Cookie 或密码。文件可命名为“巡境-设备巡检与异常闭环演示”，并在视频开头标注“Gazebo 仿真验证”。

录屏后自查：每个功能画面是否来自真实操作或明确标注的历史记录，是否保留失败/复核情形，是否能从任务追溯到图片、设备、规则和处理过程。
